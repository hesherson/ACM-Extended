# ACM Extended 1.2.3 B169

## Root fix: own the medical-menu renderer outside ACE's final lifecycle functions

The B168 runtime test still reproduced a visible medical menu whose action rows stopped responding after closing the
Narc Box. The supplied RPT showed the decisive startup warning:

`Attempt to override final function - ace_medical_gui_fnc_onmenuopen`
`Attempt to override final function - ace_medical_gui_fnc_onmenuclose`
`Attempt to override final function - ace_medical_gui_fnc_updateactions`

That means a fix which depends on replacing ACE's final menu lifecycle functions is not a reliable ownership boundary
in this load order.

B169 moves renderer ownership into ACME's existing `ace_medicalMenuOpened` event handler, which ACE emits for every
medical-menu display.

For every newly opened medical menu, ACME now:

1. assigns a display-generation epoch;
2. synchronously runs `updateActions` once so the new action controls have live callbacks immediately;
3. creates an independent ACME PFH tied to that exact display + epoch;
4. drives ACE's normal `menuPFH` from that independent PFH;
5. retires ACE's unqualified global `ace_medical_gui_menuPFH` on the following frame;
6. removes the ACME PFH only when the exact display generation unloads.

A stale unload from an older display cannot touch the new renderer because it does not know or own the ACME renderer
handle.

## Why this matches the failure signature

Closing the Narc Box returns through:

`fn_skClose -> ACME_fnc_reopenMedicalMenu -> ace_medical_gui_fnc_openMenu`

When the returned display did not have a live renderer driver, action buttons kept the last painted controls/handlers
and appeared inert.

Direct Pressure appeared to repair the menu because it explicitly forces an `updateActions` pass. Tourniquet also
recovered it by running another normal treatment/display lifecycle.

B169 removes that dependency. A freshly returned medical menu receives an immediate action bind and then remains
continuously driven by the display-owned renderer.

## Scope

No Narc Box-specific treatment exception was added.
No CPR-specific action exception was added.
No Direct Pressure or tourniquet recovery hook was added.
The fix is the shared medical-menu renderer owner used by all returned/recreated medical menus.
