# ACM Extended 1.2.3 B167

## Head Tilt-Chin Lift and manual Semi-Fowler menu return

B167 fixes the shared continuous-action lifetime that could leave the medical menu unavailable after Head Tilt-Chin
Lift or provider-held Semi-Fowler.

The important regression was in the generic continuous-action controller. These two maneuvers are non-dialog,
hands-on continuous actions. The controller initializes `ContinuousAction_ShouldReopen` to false, while BVM/CPR
have their own explicit menu-return paths and dialog actions have separate UI ownership. Head Tilt-Chin Lift and
manual Semi-Fowler never opted back into a medical-menu return, so a normal mouse/Escape/movement cancellation could
finish the hold and simply leave the provider outside the medical menu.

B167 adds an explicit per-episode `reopenOnEnd` option to `beginContinuousAction`.

- Head Tilt-Chin Lift opts in.
- Unsupported/manual Semi-Fowler opts in.
- BVM, CPR, stethoscope and other existing callers retain their current behavior by default.
- If the medical menu is already open for the same casualty, cleanup does not destroy and recreate it.

The startup grace no longer closes a medical menu which the provider explicitly reopened to leave the hold.

## Stale continuous-action lock recovery

The shared continuous-action heartbeat is now written only **after** the action-specific per-frame callback completes.

Previously the heartbeat was refreshed before the callback. If an action-specific callback threw, the generic
controller could keep advertising a fresh heartbeat every frame before hitting the same error. Stale-state recovery
would therefore consider the broken controller healthy indefinitely, which is consistent with the reported state
where later medical buttons appeared to do nothing.

With B167, an action-specific per-frame failure stops refreshing liveness and the existing bounded stale-gate recovery
can retire the orphan.

The controller also now returns an explicit Boolean indicating whether it actually acquired the provider.

## Head Tilt-Chin Lift

`fnc_beginHeadTiltChinLift.sqf` no longer rejects the shared `ContinuousAction_Active` flag before calling the
shared controller. This is deliberate: `beginContinuousAction` owns the stale-session recovery and the real
exclusivity decision. A stale flag can therefore self-heal instead of making the 1 ms Head Tilt launcher silently
do nothing.

The exact Head Tilt generation still owns its patient reservation and mouse handlers. Its normal cancellation path
still releases only that generation.

## Manual Semi-Fowler

Provider-held Semi-Fowler likewise no longer rejects the raw global continuous-action flag before the shared
controller gets a chance to classify it.

If a genuinely live competing continuous action still owns the provider, acquisition returns false and the unsupported
Semi-Fowler episode is laid back down normally. If the gate was stale, the shared controller recovers it and starts
the requested hold.

## Opening the medical menu

Opening the ACE medical menu while the provider is actively maintaining Head Tilt-Chin Lift or manual Semi-Fowler is
now an explicit cancellation request for that exact hands-on generation.

The menu-open event checks the current continuous-action session against:

- the patient's exact Head Tilt session; or
- the provider's exact manual Semi-Fowler hold.

Only those two non-dialog holds are cancelled. BVM, CPR, auscultation and unrelated continuous actions are not
blindly cleared.

The medical-menu crouch animation is not acquired on the same frame as that cancellation, allowing the old hands-on
provider controller to run its authored exit without another pose controller fighting it.

The treatment bridge intentionally does **not** cancel those holds again when a button is clicked. Doing so in the
same frame as starting the successor treatment could increment the shared continuous-action epoch before the old
PFH executed its `onCancel`, leaking the old patient reservation.
