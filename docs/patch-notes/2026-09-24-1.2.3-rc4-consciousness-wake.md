# ACM Extended 1.2.3 RC4 — Consciousness Wake Repair

Date: 24 September 2026  
Build: B147  
Debug revision: rc4

## Root cause

The September 22 wake-state reconciliation work changed the medical state-machine WakeUp condition to the shared `ACM_core_fnc_canWake` function. CBA invokes state-machine transition conditions as `_listItem call _condition`, so the function receives the casualty object directly as `_this`.

The new gate expected an argument array. The auxiliary `ace_medical_WakeUp` event observer made the same incorrect assumption. Eligible wake events could therefore type-error inside the shared path before the transition completed. Because ammonia inhalant, Slap Awake, Shake Awake, spontaneous wake logic and fracture pain all converge on that WakeUp path, they all appeared broken at once.

## Fix

- `ACM_core_fnc_canWake` accepts both direct casualty-object calls and `[_patient, _ignoreKnockOut]` calls.
- The medical-state-machine WakeUp condition explicitly wraps the CBA list item before calling `canWake`.
- The ACME WakeUp event observer accepts both the direct object payload and an array payload.
- Fracture-pressure pain now calls `ACM_core_fnc_requestWake` directly.
- Forced-unconscious clinical gates remain unchanged.

## Acceptance

1. Create a stable unconscious casualty with no sedation, paralysis, seizure or cardiac arrest.
2. Confirm ammonia inhalant can wake the casualty.
3. Confirm repeated Slap Awake attempts can wake according to the existing probability curve.
4. Confirm Shake Awake can wake according to its existing probability curve.
5. Apply Direct Pressure over a confirmed fracture and confirm the painful stimulus can wake according to the existing ammonia-style probability curve.
6. Confirm all successful wake paths leave treated casualties down/lying where appropriate instead of standing them automatically.
7. Confirm adequate sedation or rocuronium still blocks these wake stimuli.
