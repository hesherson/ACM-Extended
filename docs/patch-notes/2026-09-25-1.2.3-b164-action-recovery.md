# ACM Extended 1.2.3 B164

B164 repairs the action-execution regressions reported after B163.

## Semi-Fowler

B162 changed `chestAccessFrontRoll` from a provider-only animation request into the complete staged roll pipeline:
provider `medic4` -> canonical casualty `chestSealRoll`.

`fn_headElevateStart.sqf` still called `chestSealRoll` directly immediately after dispatching that same staged
provider request. A posterior-up casualty therefore received two competing normalization requests. The second lease
could block or supersede the first and leave Semi-Fowler after its treatment timer without ever reaching the lift.

B164 restores the original ownership boundary. `chestAccessFrontRoll` is provider theatre only again, while
Semi-Fowler owns exactly one canonical casualty roll in parallel. Chest-seal workspace entry now has a separate
`chestSealEntryFrontRoll` operation for the intentionally staged provider-then-patient choreography requested for
that minigame. This prevents a chest-seal presentation change from silently changing Semi-Fowler semantics.

## Narc Box, capillary refill and other ordinary actions

B162/B163 added a global anatomy transformation to every collected medical-menu action row. The first B162 form
produced the RPT `Type Bool, expected Array...` failure and removed all buttons; B163 corrected that runtime error,
but still routed every unrelated action through a new presentation transform before execution.

B164 restores the B161 direct-action path. The renderer no longer rebuilds/filter-transforms the whole action array.
Narc Box, capillary refill, Semi-Fowler and other direct rows retain their original condition and statement closures.

The wrong-body-part submenu protection is retained only where it is actually required: inside grouped dropdown
bucketing, immediately before the renderer replaces an expanded child condition with `{true}`. This prevents stale
Chest/IV/airway dropdown children from leaking onto the wrong anatomy without touching unrelated direct actions.

## RPT

The supplied 15:02 RPT contains no new action-time SQF exception corresponding to these failures. This is consistent
with a logical presentation/ownership regression rather than another thrown script error.

When ACME debug is enabled, B164 also writes `[ACME TREATMENT] started/success/failed` lifecycle markers for each
medical treatment. If any timer-only action survives this patch, the next RPT will show whether ACE completed or
failed the progress action and the exact treatment class/body part involved.
