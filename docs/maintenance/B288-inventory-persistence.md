# B288 prepared-equipment persistence

Opaque prepared IV sets and syringes require both native inventory and ACME metadata from the same settled checkpoint. A native magazine's ammo is an identity, never its medication dose. Saving only `getUnitLoadout` cannot reconstruct mixtures or exact remaining volumes.

`[_holder] call ACME_fnc_inventorySnapshot` returns `[1, rows]`; each row is `[kind, sourceToken, nativeClass, payload, tiedPatientRef]`. The supported kinds are `prepared` and `syringe`. Coolers keep their separate versioned snapshot and normalized clocks. `[1, []]` is a valid empty snapshot. `[]` means that custody, import funding, placement or an edit is unsettled, or that a native carrier cannot be identified safely. The caller must defer the entire native-plus-metadata save.

`[_holder, _snapshot] call ACME_fnc_inventoryRestore` runs on the holder's owner, after restoring native inventory. It validates the whole snapshot and all source tuples before removing anything, then exchanges each exact class/ammo tuple for a fresh SID and native token. A funding journal retains removed sources if enqueueing fails. Repeating the same application retries it or is inert once complete; deliberately restoring the whole saved native loadout again supplies a new funded application. A retired kit or locality period cannot borrow an incomplete prior application's funding. `true` means every exchange was enqueued; the checkpoint readiness API still waits for registration and native placement to settle.

Both APIs support a person or an object such as a crate. Syringe medication, measured drug and saline volumes, component recipes, label, color and three tag lines are retained. Prepared IV/Y sets retain linked medication components and exact remaining volumes. Owner/patient runtime references and infusion clocks are rebuilt. The API does not recreate a running treatment or input session.

Fresh whole-blood prepared sets also carry donor survival, blood type and normalized collection age in optional prepared-row slot 11. A restored set uses that immutable inline metadata; an old numeric donor-registry suffix cannot bind to an unrelated donor after restart. Missing donor metadata remains explicitly fenced instead of being refreshed from a reused ID.

Patient-tied removed sets remain tied. Their reference uses `ACME_fnc_clinicalObjectRef` with a mission-incarnation fence and an optional mission-assigned durable ID. Unresolved cross-restart references become an unusable patient tie instead of matching an unrelated reused `netId`. A mission adapter can bind recreated objects through `clinicalObjectRef` before import, or explicitly pass a third argument to `inventoryRestore`: a hashmap mapping saved patient net IDs to recreated patient objects. Only supply mappings from the mission's own durable identities.

The aggregate equipment snapshot also carries worn nested containers in optional slot 5: `[clothingSlot, childClass, cargoTree]` entries, where clothing slots 0/1/2 mean uniform/vest/backpack. Older five-field equipment snapshots remain validated. The bounded cargo trees include native contents, prepared-equipment metadata, cooler metadata and child trees. Restore matches existing physical children once each, never refills them on retry, and waits for native grants before completing. Returning a removed vest enrolls its newly recreated child objects for custody adoption. Loose blood inside these nested or removed-carrier cargo trees is currently refused because the four-field tree has no exposure-ledger slot. Move those bags into ordinary top-level inventory before a coordinated checkpoint; do not save a failed snapshot as empty metadata.

Legacy native `ACM_Syringe_*` magazines can still reconstruct their encoded medicine and quantized volume through the existing importer. Do not persist a second independent copy of `ACME_narcStore` alongside their opaque carrier metadata: that would duplicate the same preparation.

## Identity across server restarts

The server reserves blocks of 256 native IDs in the server profile before issuing them. Keep the server profile with mission saves. After restart, unused IDs in a reserved block are abandoned rather than reused. This removes the old sequence-from-zero collision on the same server profile. Explicit metadata imports also exclude saved source IDs from replacement allocation, including when migrating to a fresh profile. The exclusion is part of the same funded registration publication as the preparation, so a network event cannot overtake it.

The native magazine domain contains 65,534 usable IDs. A once-per-mission RPT warning starts at 60,000 so operators can migrate while equipment is still fully settled. Allocation fails closed at exhaustion or when the profile high-water mark is malformed; funded preparations remain pending in the current mission and a diagnostic is written. This is a finite budget across missions using that server profile. **Migrate fully settled snapshots before exhaustion.** Blocked funded pending preparations cannot pass the normal checkpoint API, and this build has no administrative importer for that pending state. Do not shut down expecting those runtime journals to survive. Profile writes are an engine/disk boundary: writable durable profile storage and retaining the profile are required. Resetting, rolling back or switching profiles removes the raw-token restart guarantee. Migrate through complete metadata snapshots and restore APIs; old raw native saves alone are not a supported migration format.

As a second fence, adoption, reservation and every server mutation reject a second claimant while the certified prior holder still physically contains the same token. A real transfer waits for prior-custody replication to clear; a duplicate cannot steal the current holder's medication or custody. This conservatively defers a contested tuple and never invents another dose to resolve it.

SQF execution regressions cover the allocator's reserve-before-issue ordering, simulated restart gaps, invalid/exhausted profiles, duplicate-token rejection, exact dose round trips, malformed saves, failed removals, funding retries and kit retirement. Native Arma cargo replication, actual profile-file durability and a mission's save adapter still require in-engine acceptance.
