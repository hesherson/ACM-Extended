Base: `7c9d20682f34f1d56e2df1421352c4f8a36f2838` (B206). Public version remains `1.2.4.1`.
Runtime identity: `B207 | NA7-B207-1.2.4.1-stable`.

## Changes and purpose

| Area | Change | Failure addressed |
| --- | --- | --- |
| DP/Hang admission | Shared patient-owner validation checks machine identity, locality, epoch and request age. Requests older than five seconds are rejected. | Late or reset-era acquisition resurrecting an action. |
| Cancellation/replay | Replicated patient history retains exact tokens and terminal cancellations for eight seconds, capped at 64 records. Saturation refuses unknown claims instead of evicting live cancellation evidence. | A release delivered before its request; replayed acquisition; stale release affecting a replacement. |
| Direct Pressure | Duplicate active acknowledgements are ignored. Local serials distinguish rapid requests. Owner-granted acceptance deadlines and exact claim tokens fence activation and patient-side updates. The medical-menu bridge returns whether the request was queued. | Duplicate ACK releasing an active hold; a late ACK or marker overwriting a replacement; a delayed clot update crediting a restarted hold; an asynchronous start reported as immediate failure. |
| Hang Bag | Monotonic request/ACK sequences, exact numeric episode keys and a precision-aware episode increment. Only a new valid renewal changes the lease/flow. | Reordered replies stopping a new hold, replay extending a lease, rounded timestamps merging separate episodes during long missions. |
| Continuous actions | Record the actual provider, patient, generation and original cancellation worker before startup. Existing recovery uses that record and releases the matching controller once. | An incoming medic replacing another medic's controller; interrupted startup/frame callbacks leaving patient/input state stranded. |
| Treatment sound | The accepted DP claim owns the one-shot sound. The core treatment override no longer broadcasts that sound globally. | Duplicate/global playback before owner acceptance; a previous source audit missed core overrides. |
| Carrier workload | Synchronous enrollment plus locality/init hooks maintain an active patient list. A fallback world scan runs every 30 seconds; active checks retain their 0.2-second cadence. | Repeated full-world scans five times per second. |
| Ventilator discovery | Nearby candidate discovery runs every 0.5 seconds, or on listener/vehicle change, and includes vehicle crew. The existing 0.05-second beep timing remains independent. | Nearby searches at 20 Hz and omitted embarked patients. A newly discovered alarm may take up to one discovery interval to enter the candidate list. |
| Installation verification | All 14 PBOs contain build/protocol/component stamps. Server, player and HC manifests are compared through targeted, finite handshake attempts. | Mixed builds passing a check that merely compared local constants. Missing replies remain explicitly unverified. |
| Diagnostics and CI | Opt-in local sampler; strict outcome comparison preserves testcase occurrences and rejects new failures/skips, missing cases, malformed reports and fatal exits. | Insufficient live evidence and new regressions hidden outside a hand-selected test list. |

The compatibility exchange is diagnostic, not authentication. It does not kick players or add treatment-permission gates. There is no recurring compatibility PFH. Attempts run at approximately 3, 10 and 25 seconds with a terminal timeout at 45 seconds; a late valid exchange can recover an unavailable result. Disconnect cleanup removes peer manifests and keeps only a bounded list of retired machine IDs.

The claim ledger adds bounded replicated transaction state. This is a correctness tradeoff, not a claim that every action now sends fewer publications. Existing snapshot periods remain nominal scheduling intervals, not guaranteed delivery deadlines under server stalls. No physiology formula, drug dose or flow multiplier value is changed.

Direct Pressure's first activation must arrive within the original three-second grant deadline. Replayed replies do not extend it, and an already-active duplicate cannot cancel its hold merely because that deadline has passed. Marker/clot updates carry the originating claim token and epoch; the patient owner checks them against its current reservation. The provider allows three seconds for initial claim replication or a transient mismatch before stopping a persistently lost claim. This grace affects local presentation convergence only; it does not authorize stale clinical writes.

Positive internal marker/clot calls without a claim token now reject. All in-repository callers supply the accepted episode; mission integrations should enter through `ACME_fnc_directPressureStart` instead of invoking those internal effects directly. Tokenless legacy negative cleanup remains limited to sites with no reservation.

## Deployment and live acceptance

Use `tools/Deploy-ACME-B207.ps1` from the updated branch at `F:\ACM-Extended`. It requires a clean tracked checkout, validates B207 identity, runs `hemtt check` and `hemtt release`, verifies 14 PBOs with signatures and one key, and copies the complete release into the installed mod directory. Optional `-ModPath` and `-ServerKeysPath` select existing explicit destinations.

Install the same complete package on server, clients and headless clients and restart Arma. Check local and server verification status, not only the public version number. Detailed collection commands and the dedicated-server/two-client/HC matrix are in [the B207 live validation runbook](2026-09-30-b207-live-validation.md).

Live dedicated-server validation and Windows asset binarization remain pending in this environment. Test the actual unit modpack, ownership transfers, cancellation under latency, JIP, vehicles, animations/PhysX and a representative load soak before broad rollout. A cancellation callback that itself fails can still leave action-specific cleanup incomplete; the controller deliberately retires its record before cancellation to prevent duplicate inventory/clinical side effects. RPT review remains part of the live gate.
