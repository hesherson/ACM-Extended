# B155 validation

Base: published B154 `652183b6714f280fd155435152631d11b33c0f43`.

## Observed defects and coverage

The chest-entry tests execute the real Open, Close, provider and pose code with
explicit native-animation, UI, object and network substitutes. Three regression
cases fail with the unchanged B154 pose implementation: late first observation of
medic4, missing its final frame, and never observing the finite state. The patched
entry/pose cases pass, including exact episode ownership and delayed owner packets.

Patient tests execute the preparation continuations with deliberately late delivery:
carrier removal cannot publish completion before its later lowering callback;
Semi-Fowler and prior rolls must actually finish; valid foreign animation leases
are respected; cancellation and reopening invalidate old callbacks. A broader run
caught loss of the original restoration snapshot during reopen. The final correction
retains that snapshot while restarting preparation, and the affected suite passes.

## Test results

All commands use `PYTHONDONTWRITEBYTECODE=1`, `python3 -B -m pytest -p no:cacheprovider`,
and explicit `SQFVM` / `HEMTT_BINARY` executable paths. No runtime cases were skipped.

| Run | Result |
| --- | --- |
| IV hover, geometry, PAA container and UI follow-up | 105 passed |
| Debug overlay, assessment, seizure, compatibility, version, font, expansion bootstrap and pending heartbeat | 76 passed |
| Broader chest/pose/weapon/menu/head/CPR regression discovery | 458 passed; one reopen-state defect found and corrected |
| Final affected chest-entry, preparation, workspace, menu, head completion, CPR contract and heartbeat/banner suite | 207 passed |

These rows overlap; they are not an additive test total. The final 207-case run
includes the corrected reopen case, all 20 preparation-progress cases, six pending
heartbeat/banner cases, and the finalized provider ownership checks. The other
broader-regression cases were unaffected by the final patient snapshot correction.

The native function-registration, public-version, ACE override load-order and ACE
override-target gates pass. Current coverage is 389 PREP registrations, 69 explicit
CfgFunctions sources and 69 frozen ACE override targets (68 supplied upstream
sources plus one documented compatibility owner). `git diff --check` passes.

The shared test adapter now matches command-token boundaries, avoiding accidental
replacement of `stance _p` inside `distance _p`. Its regression and weapon-preflight
cases pass. Existing lifecycle fixtures now accept CBA's optional timeout argument.

## Release packaging

HEMTT **1.22.0**, `hemtt release --no-bin --no-archive`, succeeds:

- 1,634 compiled SQF files, 16 rapified configs and 12 stringtables.
- 14 PBOs with matching signatures and one `ACM_1.2.3.0.bikey`.
- 51 packaged SQF/PAA files compared byte-for-byte with current source, including
  every modified SQF, all 20 IV textures and all retained compatibility sources.
- All 13 required runtime compatibility markers are present in those packaged files.
- No Python bytecode or cache directories are included in the PBOs.

The existing lint suggestions and unavailable online wiki fallback do not prevent
the build. This Linux check skips Windows model/animation binarization; use ordinary
`hemtt release` for the Windows deployment build.

## Runtime limits and references

No Arma dedicated server or renderer ran in this environment. These checks do not
prove native UI ordering, live modpack binding ownership, network delivery or
performance on the reported low-tier client. Deploy the complete fork, disable the
separate original ACM mod, restart clients/server and verify the B155 stamp plus
`[ACME COMPAT] OK`. Recheck chest entry, cancel/reopen and low-frame-rate behavior.

The supplied old mixed-install log and its external errors are documented separately
in the [RPT audit](2026-09-25-b155-rpt-audit.md); this patch does not claim to repair
all errors belonging to the wider modpack.

Engine/API boundaries were checked against the primary documentation:
[getUnitMovesInfo](https://community.bistudio.com/wiki/getUnitMovesInfo) identifies
index 1 as elapsed move time and index 2 as duration;
[CBA waitUntilAndExecute](https://cbateam.github.io/CBA_A3/docs/files/common/fnc_waitUntilAndExecute-sqf.html)
defines a negative or omitted timeout as no timeout. Cancellation remains explicit
in the owning preparation conditions.
