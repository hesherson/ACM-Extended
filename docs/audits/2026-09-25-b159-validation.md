# B159 validation

## Findings and scope

The EJ overlay owns control IDs 7290020 and 7290021. Junctional packing also used those IDs, so the junctional renderer overwrote their textures and both handlers changed the same controls' visibility. The original registration order creates the packing pictures first; EJ creation then sees existing controls and leaves the wrong texture in place. Zone 3 REBOA is independent of this collision.

Packing now uses 7290040 through 7290043. Existing EJ geometry and selection IDs remain intact. The chest seal body image already read native and detailed penetrating-wound seal records, but omitted the separate `ACME_thora_sealed_left/right` records. It now includes those when no chest tube occupies that side. Physiological state and wound coloring are unchanged.

## Regression execution

59 checks passed using SQF-VM:

```text
addons/acm_extended/tools/test_b159_body_icons.py
addons/acm_extended/tools/test_historical_junctional_execution.py
addons/acm_extended/tools/test_build_version_tag.py
```

The 16 new cases execute the actual overlay code with mocked engine controls. The shared registry models control creation, ID lookup and retained texture/visibility values. Cases cover both handler orders, repeated draws, bilateral EJ with Zone 3 REBOA, concurrent packing, unilateral EJ removal, switching to a clean patient, native and detailed anterior/posterior chest seals, left/right/bilateral surgical seals, secured tubes, wasted seals, sutured closure and seal removal. The prior junctional suite checks its clinical workers and live/dead evidence layers.

The same EJ and surgical-seal checks were run against the B158 source. Both reproduced the reported defects before the fix. The initial new chest test cleanup used a namespace nil value unsupported by this VM's default-value emulation; cleanup was corrected to the explicit false/empty-array reset values used by production. The final run passed all 59 checks without skips.

## Build and deployment

HEMTT `release --no-bin --no-archive -v` completed successfully with 14 PBOs, 14 matching signatures and one public key. The three changed runtime SQF files were compared byte for byte against the packaged sources. Existing HEMTT style suggestions remain.

The deployment script defaults to the repository root, checks the B159 marker and clean tracked files, builds, checks the release count and matching signatures, and copies individual release files into the existing addon/key directories. It never replaces or deletes source directories. Generated release output cannot be chosen as its own copy destination.

Windows PowerShell is unavailable in this Linux environment, so the deployment script received source review rather than Windows execution. SQF-VM checks do not render Arma textures or simulate real multiplayer replication. Final icon appearance and the Windows copy operation require the user's normal deployment and in-game check.
