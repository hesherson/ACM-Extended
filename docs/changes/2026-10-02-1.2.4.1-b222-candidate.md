## Mask CPAP workflow

Select **Head > Advanced > Connect Mask > Ventilator (CPAP)**. The carried ACME ventilator includes the abstract mask interface; there is no additional mask inventory class. Then open the patient's ventilator, power it on, review its settings, and confirm/start ventilation. The attach transaction itself does not power or start it.

The action uses the existing ventilator skill setting and ACE shared-equipment policy, including the optional EFAK-aware item bridge. Standing, crouched and prone awake patients use the same action; no player-versus-AI filter is added. A non-rebreather must be removed first. Existing invasive connection and removal actions remain.

Mask suitability is independently checked at visibility, server reservation, UI start and patient-owner delivery boundaries. The game requires a living, awake, spontaneously breathing patient without cardiac arrest, paralysis, Recovery Position, an ETT/i-gel/cric, or an NRB. These are simulation gates, not clinical treatment instructions.

A physical mask flag is separate from the saved device interface dial. Choosing NON INVASIVE on a carried or intubated device does not create a mask. Mask attachment starts in CPAP PS HF with pressure support zero; settings can be reviewed on the normal parameter pages. Global Simple mode does not convert mask support into mandatory breaths or hide its settings. Mask CPAP cannot produce apneic backup or manual rescue breaths. Existing secured-airway Simple/advanced behavior remains in place.

Power, battery, circuit and patient suitability gate delivery. Deterioration stops effective support and uses the existing high-priority circuit alarm; it does not force wakefulness or create an airway. A debit acknowledged after deterioration leaves the acquired device attached but stopped, so it can be recovered normally, rather than losing or duplicating it. Device custody, shared supplies and return receipts retain their existing exactly-once paths. NRB and mask CPAP cannot be stacked.

No new mask model/animation or physiological calibration is claimed. This connects and constrains the existing ventilator model; live rendering, actual EFAK compatibility and multiplayer behavior remain acceptance-test work.

## Suction operation

Continuous SALAD parking still requires ACCUVAC, the held suction tool and its tip inside the mouth. MMB parks it and frees the hand; another distinct press removes it. A manual suction bag remains hand-operated. Inventory eligibility still honors the shared-equipment policy and EFAK availability; this patch does not generate missing supplies or bypass a failed kit synchronization.
